MPC planning and learned selection of LLM responses

This voltage-control extension follows Awareness → Planning → Simulation → Verification → LLM Optimizer, then prepares an operator record. MPC and SAC now enter as explicit initial candidates. Three actual local-model responses form a refinement pool. A contextual bandit learns which canonical operation to spend one additional simulation trial on.

Read the outcome before assuming an advantage. Voting, learning and language generation can add cost without improving a capable numerical baseline. The tables below preserve ties, rejected trials, worse outcomes and model-scope failures. The response selector is separate from the SAC controller and does not fine-tune Llama.

Use this lesson after V1–V5/A1–A2 in the main workshop. Its eight checkpoints E1–E8 match the added LaTeX slides. Run all cells in order. Default execution reads saved experiments and demonstrates one selected-feedback update; it makes no new Ollama or power-flow calls. Data generation took place separately, with actual raw calls and fresh numerical evaluations saved alongside the notebook.

E2 — MPC and SAC propose; numerical checks decide admissibility

MPC uses an explicit model over a horizon of three forecast steps. SAC uses a previously trained continuous-action policy. Both proposals receive fresh first-action simulations. Their declared current-step objective is

\[ J(a,b)=(1-a)^2+0.05b^2+10\operatorname{mean}[(V-1.01)^2]+0.05\|[a,b]-u_{\mathrm{previous}}\|_2^2. \]

Here \(a\) is the common-fleet active fraction, \(b\) the reactive fraction, \(V\) the modeled voltage vector in per unit, and \(u_{\mathrm{previous}}\) the previous action. These weights define a teaching objective. Improving this score does not establish improvement of MPC's separate full-horizon objective.

The two tables use the same physical test scenario. MV LinDistFlow omits internal LV and transformer constraints; OpenDSS covers the supplied MV/LV circuit. A lower score from one model is therefore not a directly comparable physical operating benefit over the other model.

E3 — Read actual Llama and Qwen responses before voting

Each model receives identical numerical evidence and a bounded menu: increase active fraction by 0.0025, reduce reactive magnitude by 10%, decrease active fraction by 0.0025, or keep the incumbent. These are intentionally small local trials, not a globally optimal search.

Canonicalization groups identical tool/parameter payloads. The vote counts actions rather than prose. Public reasons are displayed verbatim, including imperfect explanations. They are not electrical proofs or hidden chain-of-thought. All three calls are paid for before either majority or learned selection occurs. E4 — Observe one real reward update and the full training record

The optimizer uses LinUCB, a linear contextual-bandit method. Its action is an LLM-proposed operation. It learns a reward preference from operating context and vote share; it does not learn the quality of a model's prose or choose which single model to call.

For feature vector \(\varphi\), information matrix \(A\), reward accumulator \(b_r\), and coefficient vector \(\hat\theta=A^{-1}b_r\), training selects the largest predicted reward plus an uncertainty bonus. Only after selection does it read that operation's outcome and update \(A\leftarrow A+\varphi\varphi^\top\) and \(b_r\leftarrow b_r+r\varphi\).

The declared reward is \(\min(1,\max(0,J_{inc}-J_{trial})/0.01)-0.01\) for a feasible trial and \(-1.01\) for rejection. The final acceptance gate is separate. The 0.01 trial penalty is a fixed teaching cost, not measured seconds. The common three-call generation cost cannot be saved by a post-generation selector.

The cell reproduces the first actual selected-feedback update, then loads the full frozen policy. The graph shows the recorded training rewards, not a convergence or generalization guarantee. Each of five predeclared training orders uses one pass of 24 scenarios. Validation never chooses hyperparameters or checkpoints.

E5 — Compare against numerical search, voting and fixed responses

All common-pool methods use the same three responses and one selected response trial, plus a distinct final recheck. “Fixed pool response” chooses a predeclared model's reply from that shared pool; it is not a one-call deployment latency experiment. The fixed numerical operation generates no LLM responses. Best-of-all evaluates every unique response and has a larger budget.

A final, explicitly post-hoc diagnostic shows every permitted fixed numerical rule without LLM calls. It helps determine whether the observed action pattern itself needs learned selection. No rule is tuned on the test set or substituted for the primary declared comparator.

The learned policy remains frozen on all 12 test contexts. Uniform selection includes a predeclared primary draw and a sensitivity analysis. A small paired interval is descriptive and conditional on this feeder, scenario distribution, response archive and training protocol. Inspect the signed difference: a negative learned-minus-baseline objective favors learning.

E7 — Include the cost of generating the response pool

These durations are actual local Ollama calls. They include the call's host behavior and can vary with model loading, residency and hardware. Collection was batched by model. The sum of recorded components is labeled an accounted serial time, not a stopwatch measurement of an online control-room workflow. Cached notebook execution is different again.

The learned selector can improve trial allocation, but it cannot recover time already spent generating all three responses. A pre-call model router would need a different experiment. Prior SAC training, dataset generation, human review and hardware dispatch are outside these online component totals.

What this adds to the three-use-case tutorial

The voltage pilot demonstrates the requested separation: model-based planning, a model-free alternative, model execution and verification, multiple actual language responses, voting, reward-based selection, and human review. Whether any selector improves the conventional method is an observed result, not an assumed architectural benefit.

Restoration continues with its MILP method lesson and verified feeder action catalog. Cyber response continues with protected-state WLS and constrained redispatch. Both execute the five proposal stages in P4–P6, but this notebook does not claim new SAC policies or trained response selectors for those cases. A receding-horizon extension must define the switching or security states over time before being called MPC.
