\subsection*{2. What is agentic AI?}
\textbf{Timing:} 00:30--01:30 (1 minutes)\par
\textbf{Slide content:} An LLM agent works toward a goal by choosing tools, reading their results and choosing what to do next.\par
\textbf{Teaching notes:} Use the architectural definition in Anthropic, Building effective agents: an agent lets the LLM direct its process and tool use. Agentic AI is a broad term; here it means a system organized around this bounded loop. An AI agent is the component that chooses and follows steps. A tool is a permitted software function that returns a result. Point to the goal, model choice, executable tool, returned evidence and feedback arrow. The application stores case facts and prior results as the context supplied at the next model request. If a required check is missing, the outcome remains HOLD. Stop or return a proposal only under the fixed workflow rules. Do not imply that feedback alone establishes agency: conventional programs can also branch and loop. Our default notebook calculates engineering results now but replays the actual old Llama choices. No live model service is needed. Stanford source: Monica Lam, CS224V Agentic AI, Lecture 1: Introduction, Fall 2026, p.2 describes function calling and agentic workflows. The goal-and-feedback drawing is our grid teaching adaptation, supported by the separate bounded-agent architecture citation. This is not an original Stanford power-system diagram.\par

\subsection*{3. Stanford: tool calls become a workflow}
\textbf{Timing:} 01:30--02:30 (1 minutes)\par

The class replays those old model choices while numerical cells calculate current results. Source lecture figure is shown unchanged within the documented crop.\par
