Presenter script: three operator cases

Alaa Selim, MIT/Dartmouth; Mohamed Chehada, UT Austin.

50 concept slides, 90 minutes and three what-if discussions. Explain each operator problem before following the agent request, tool result and human decision. No software or account is needed.

The numerical results and model replies are prepared examples. Separate recorded studies retain their own inputs and scope. One Llama model fills two roles in the implemented five-role Python workflow. No teaching example operates equipment.

The five roles share the same case facts and checked results. One Llama model handles planning and refinement. Python calculates and checks. Awareness reads the shared case. Agent roles in the three recorded cases

Solar settings: recorded medium-voltage study

  1. Awareness: read the case / Python: Read the load, forecast, current allowance and MV model scope.
  2. Planning: choose a trial / numerical tools and Llama: Prepare MPC and saved-SAC candidates. Llama can request the declared initial studies or return review.
  3. Simulation: calculate / Python: Calculate the effects of each candidate using the declared three-phase linear model.
  4. Verification: check / Python: Check case matching, voltage, current and inverter limits. Only passing candidates receive eligible scores.
  5. LLM optimizer: refine / Llama, with a Python guard: Request less reactive power, then more PV output. Recalculate and check every changed setting. Python selects by verified cost and performs a final recheck.

Selected final current use: about 50.75% of the allowance. This recorded medium-voltage study has its own inputs and scope. The operator still reviews scope and missing checks.

Restoration: recorded feeder-catalog study

  1. Awareness: read the case / Python: Keep the fault, available ties, critical loads, service goal and model scope in the shared case record.
  2. Planning: choose a trial / numerical tools and Llama: Prepare the stated restoration catalog options; request the initial evaluations or review.
  3. Simulation: calculate / Python: Calculate total and critical service and the current used by each option.
  4. Verification: check / Python: Reject the SHED_065 trial at about 111.01% of allowed current. Keep the passing SHED_075 trial eligible.
  5. LLM optimizer: refine / Llama, with a Python guard: Request bounded catalog changes and rank passing IDs. Python corrects the wrong cost order and rechecks the chosen plan.

Selected final service: about 1,843.61 kW total and 474.04 kW critical, at 91.87% current use. This recorded feeder study is separate from the six-node example. Physical switching order and operating permissions remain outside the result.

Suspicious readings: recorded four-bus study

  1. Awareness: read the case / Python: Read the measurements, alarm context and declared availability of assumed trusted channels.
  2. Planning: choose a trial / numerical tools and Llama: Prepare the permitted response candidates. Llama can request the initial evaluations or review.
  3. Simulation: calculate / Python: Estimate state and calculate each candidate's branch flows and correction.
  4. Verification: check / Python: Test the trust condition, stated branch limits, bounds, evidence match and DC model scope.
  5. LLM optimizer: refine / Llama, with a Python guard: Request bounded trials including TRUSTED_QP. Python ranks only passing candidates and rechecks the selected correction.

Selected correction: about 0.121694 p.u., with predicted flow 0.17000 p.u. against the 0.18000 p.u. limit. The trusted readings are assumed, not authenticated. Human review is still separate from equipment dispatch.
