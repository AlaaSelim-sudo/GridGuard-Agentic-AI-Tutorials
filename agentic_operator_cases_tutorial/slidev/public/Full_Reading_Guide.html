14. Case 1: which solar settings should we use?

Timing

Slide content
Choose settings that keep voltage and line current within the allowed range. An agent can organize the trials and return checked options.
Teaching notes
Plain-language explanation: Imagine an operator comparing possible settings for solar units. Each choice changes power flows. The job is to find an acceptable option while respecting voltage, line-current and unit limits. An agent can organize the requests and responses, while the tool calculates the electrical effects. We first learn those tools in Colab, then inspect saved agent decisions. Original source detail: The feeder is a synthetic SMART-DS Greensboro-area example, not a measured utility circuit. The command sets active- and reactive-power participation for an inverter fleet. MPC, model predictive control, uses a system model and a short forecast to calculate a plan under limits; here the proposed command is the first step of that plan. SAC, Soft Actor–Critic, is a saved controller learned from rewards. It produces a proposal from old weights without training again. The default calculation covers medium-voltage (MV) phases and MV line currents, with simplified low-voltage (LV) aggregation. Feasible means the proposal passes the limits represented by that model. Compare the penalty score J only after checking those limits; smaller J is preferred for this stated objective. Run L0 and L1 first.

68. Multi-agent framework used in this workshop

Timing

Slide content
The five roles share the same case facts and checked results. One Llama model handles planning and refinement. Python calculates and checks.
Teaching notes
The implementation names five roles: Awareness Agent, Planning Agent, Simulation Agent, Verification Agent and LLM Optimizer. Awareness reads the case. Planning prepares permitted candidates and can ask Llama which initial study to request. Simulation runs a case-specific numerical tool. Verification checks limits, case identity and model scope. The optimizer requests bounded changes or ranks passing candidates. Every changed trial returns to simulation and verification. Python guards the ranking and performs a final recheck before operator review. One Llama model serves the planning and optimizer roles; the other stages run in Python. This is a custom role-based Python workflow, not five independent language models and not a live multi-agent run in the default Colab. The solar, restoration and cyber cases use different numerical adapters behind the same stages. The six matched comparisons have five tied final costs and one worse Llama route; the framework does not establish a general performance gain.
