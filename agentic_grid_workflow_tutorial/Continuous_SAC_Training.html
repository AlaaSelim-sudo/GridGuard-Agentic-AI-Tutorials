How was the continuous SAC policy trained?

Optional supplement outside the three-hour workshop · about 20–30 minutes to explore

The main workshop uses a saved continuous policy so participants can focus on decisions and physical checks. Here we examine how that policy was actually trained, what it observed, and what the evidence can establish. The supplied algorithm is Soft Actor-Critic (SAC). PPO is a possible extension, not a method already evaluated in this package.

The default run reads saved evidence and performs lightweight NumPy inference. It does not train, call Llama, or run a new power-flow study. Use the ordinary workshop environment (requirements_linear.txt is sufficient). Optional retraining needs requirements_training.txt and writes to a new directory.

Learning sequence: continuous action → physical-response training environment → recorded learning → exported actor → independent physical evaluation → optional new training.

Companion detail: Continuous SAC methods. Return to the workshop for the multi-agent workflow and human review.

1. A continuous action with a physical meaning

For each inverter with kVA rating $S_i$, the common fleet command is $p_i=aS_i$ and $q_i=bS_i$. This is a two-variable control problem; it does not optimize each inverter separately. The supplied fixture satisfies available active power = kVA rating.

The actor emits $z\in[-1,1]^2$, and the environment maps it to

$$a=(z_1+1)/2,\qquad b=z_2\min\{0.44,\sqrt{1-a^2}\}.$$

The mapping enforces the fleet inverter capability region. Network voltage and current still need a physical check. Positive $b$ means reactive injection in this adapter. The entropy term used during SAC training is defined in the normalized $z$ coordinates.

2. What does the learner observe and optimize?

Each observation has seven numbers: three forecast demand multipliers, previous $a,b$, permitted current fraction $\rho$, and remaining horizon / 3. Short forecast tails repeat their last value. During training, demand multipliers are independently drawn from $[0.7,1.2]$, each episode has three steps, and $\rho=1$ throughout.

The base cost balances curtailment, reactive effort, voltage deviation, and command movement:

$$\ell=(1-a)^2+0.05b^2+10\overline{(v-1.01)^2}+0.05\|u-u^-\|^2.$$

The training reward adds soft penalties from the response surface:

$$r=-\ell-40(e_v/0.05)^2-10e_I^2-2\mathbf1\{e_v>0\text{ or }e_I>0\},$$

where $e_v=[0.95-\hat v_{\min}]_++[\hat v_{\max}-1.05]_+$ and $e_I=[\hat I_{\max}/I_{\mathrm{rated}}-1]_+$. Reward penalties are not hard physical constraints. The reserve case $\rho=0.8$ deliberately changes a condition that was constant during training.

3. Where do the training rewards come from?

The training environment uses a cubic least-squares approximation to four OpenDSS summary responses. It was fitted on 240 physical samples and checked on 48 separately sampled points, with seed 2301. These fit-validation points measure approximation error; they are not the control-policy evaluation set.

The curve below compares the stored prediction and physical response for those 48 points. The diagonal is perfect agreement. A visible error is a reason to use a separate physical verifier, not to hide the sample. The environment clips predicted current fraction and mean squared voltage deviation below at zero.

Question: which validation quantity matters most when the permitted current allowance is tightened?

4. Read the actual learning record

SAC collects transitions, stores them in replay memory, and updates an actor and critic using reward and entropy. The supplied actor and critic use two 64-unit hidden layers. The entropy coefficient is fixed at 0.005. No optimizer actions or labels enter replay memory. This is reward-based training, not imitation of MPC. See Haarnoja et al. (2018) and the implementation documentation.

The next plots show one seed's training episodes. A 100-episode trailing average makes the trend easier to see. It is not a confidence interval. A violation here refers to the training surrogate. It is not a fresh power-flow result.

5. Confirm which checkpoint produced the proposals

The study uses the final checkpoint, without selecting a training checkpoint by heldout performance. SHA-256 checks below identify the supplied actor, original training checkpoint, and physical-response surface. Hash equality verifies file identity; it does not prove a model is suitable for deployment.

The NumPy actor runs the saved two ReLU layers and tanh mean output. During export, its deterministic outputs were compared with the trained implementation on three observations; the recorded maximum difference was about $6\times10^{-8}$. We also check that today's NumPy proposals reproduce the stored proposals. This path needs neither PyTorch nor OpenDSS.

Code · cell 6
hash_checks = []

6. Separate the actor from the check-and-fallback procedure

The stored policy evaluation uses three authored demand trajectories on each model. OpenDSS checks the supplied MV/LV feeder. The linear model checks MV phases with ideal LV aggregation. The same SAC weights are used for both.

The table distinguishes the raw proposal, the three-step raw rollout, and the checked first move. If the raw first move fails its fresh model check, this saved numerical study tries the continuous horizon optimizer's first move. A passing fallback is evidence for that combined procedure, not for an inherently safe SAC actor. These are the numerical study records; the main workshop's separate agentic routing and human-review results remain separate.

7. Optional: train a new checkpoint safely

Leave RETRAIN=False for the supplied tutorial. To run a new experiment, install requirements_training.txt, change the flag in the setup cell, and run the notebook again. The cell below calls the actual train_sac(seed, steps) implementation. It copies the supplied response surface to a unique new directory, temporarily redirects the module's model directory, and restores it even if training fails. Run this cell serially in its own kernel.

This starts a new policy from initialization on the same surface; it does not resume the old replay buffer or collect new physical data. The supplied single training run took about 32 seconds, but your runtime depends on hardware and package versions. New traces are displayed separately and do not replace the saved heldout evaluation above. The fixed supplied seed is 23; changing it explores training variability rather than reproducing that seed.

Code · cell 8
new_training = None
if RETRAIN:
    run_name = datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%SZ') + '_' + uuid.uuid4().hex[:8]
    new_model_dir = ROOT / 'models' / 'continuous_sac_runs' / run_name
    new_model_dir.mkdir(parents=True, exist_ok=False)
    for filename in ('response_surface.npz', 'response_surface.json'):
        shutil.copy2(MODEL / filename, new_model_dir / filename)
    original_model_dir = cc.MODEL_DIR
    try:
        cc.MODEL_DIR = new_model_dir
        new_training = cc.train_sac(seed=RETRAIN_SEED, steps=RETRAIN_STEPS)
    finally:
        cc.MODEL_DIR = original_model_dir
    print('New training saved separately:', new_model_dir.relative_to(ROOT))
    print('Fresh physical evaluation is still required before comparing this policy.')
else:
    print('Retraining skipped. Supplied checkpoint and results remain unchanged.')

8. A small scientific extension

Choose one question before changing settings:

  1. Reserve shift: randomize the permitted current allowance during training and make the reward use that allowance. Predeclare unseen sequences, then compare raw violations, objective, fallback rate, and complete workflow time under identical physical checks.
  2. Training variability: predeclare several seeds and report the distribution of heldout results. Keep all runs, including failures; do not select the best seed.
  3. SAC versus PPO: implement and actually train PPO with the same observations, action mapping, physical environment, and interaction budget. Compare repeated-run results. PPO has not been evaluated here.

Expected answer to the central question: continuous DRL can cheaply propose a control after training. Training reward and inverter capability do not certify network constraints. The model verifier, optimizer fallback, and operator review remain distinct responsibilities.
