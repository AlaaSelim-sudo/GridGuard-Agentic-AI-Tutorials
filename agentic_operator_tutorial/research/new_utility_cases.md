# New utility and energy operator cases

Reviewed 17 October 2026. Three substantial additions support the expanded tutorial. All are vendor primary sources with named customer testimony; deployment dates are unknown unless specified. The merge-ready reference dictionary is `new_utility_sources.json`; `source_map.json` was not changed.

- **AES, U01:** deployed audit assistance with explicit human review. Google Cloud and Claude are disclosed; the agent SDK is not.
- **Duke Energy, U02–U03:** a dated, named US utility planning deployment. Keep Duke's data-preparation result separate from broader AWS program metrics. Engineering software performs the physical simulation.
- **TC Energy, U04:** strongest named framework disclosure: Strands, AgentCore and Bedrock. Identify it as a North American pipeline operator with Canadian headquarters. Keep early-test accuracy and projected savings qualified.

No U05 was added. Other leads did not supply equally strong evidence for both actual agent use and a disclosed workflow/framework. Ordinary generative-AI assistants, future conference presentations and executive demonstrations should not be promoted to autonomous grid deployments.

## Official framework documentation check

- **T02, Microsoft Agent Framework:** [official overview](https://learn.microsoft.com/en-us/agent-framework/overview/), updated 25 August 2026. Supports agents using tools/MCP, explicit workflows, and state/context with human input and telemetry. Go is public preview; avoid universal feature parity claims.
- **T04, OpenAI Agents SDK:** [official SDK guide](https://developers.openai.com/api/docs/guides/agents/sdk). Supports tool/MCP integration, handoffs and orchestration, and tracing with guardrails/human review. It runs in the developer's application; do not conflate it with a managed server-side harness.
- **T06, Google ADK 2.0:** [official documentation](https://adk.dev/2.0/). Supports graph workflows with agents/tools/functions, human input, and sessions/state/memory plus evaluation and observability. This is a capability description, not evidence that AES uses ADK.
